# Phaser 3 + VenusAPI Template

A modern template for creating Phaser 3 games integrated with VenusAPI, using Vite and TypeScript.

## Features

- 🚀 **Vite** - Fast build tool and development server
- 📘 **TypeScript** - Full type safety with VenusAPI intellisense
- 🎮 **Phaser 3** - Latest version of the popular 2D game framework
- 🌟 **VenusAPI Integration** - Complete lifecycle management and platform features
- 🎨 **Modern CSS** - Beautiful styling with CSS gradients and shadows
- 📦 **Optimized Build** - Automatic code splitting for Phaser

## Getting Started

### Prerequisites

- Node.js (v16 or higher)
- npm
- Venus CLI (see the [Venus CLI guide](https://series-1.gitbook.io/venus-docs/venus-docs/venus-cli/installing-the-venus-cli)):
  - macOS/Linux: `curl -fsSL https://github.com/Zee-Series-AI/venus_cli_releases/releases/latest/download/install.sh | bash`
  - Windows: `irm https://github.com/Zee-Series-AI/venus_cli_releases/releases/latest/download/install.ps1 | iex`
  - Verify with `venus --help`

### Installation

1. Install dependencies:
   ```bash
   npm install
   ```

2. Create your game configuration (generates `game.config.json` with unique gameId):
   ```bash
   venus create-game
   ```
   
   This will prompt you for game details and create a `game.config.json` file with a unique UUID. This file is specific to your project.

3. Start the development server:
   ```bash
   npm run dev
   ```

4. Open your browser and navigate to `http://localhost:3000`

### Build for Production

```bash
npm run build
```

**Note**: Builds with **embedded libraries by default** (Phaser loaded from Venus host). Bundle size: ~272KB vs 1.75MB bundled.

For standalone HTML5 export:
```bash
npm run build:bundled
```

### Deploy to Venus Platform


**Deployment commands:**
```bash
# Quick build and publish
npm run build
venus update-and-publish-game
```

For more Venus CLI commands and options, see: https://series-1.gitbook.io/venus-docs

### Preview Production Build

```bash
npm run preview
```

## Embedded Libraries

This template uses the Venus embedded libraries system **by default**. Phaser is loaded from:
- **Mobile**: Venus host app (instant, offline-ready, 1.1MB saved)
- **Web**: CDN fallback (`venus-static-01293ak.web.app`)

**Build Scripts**:
- `npm run build` - **Default**: Embedded libraries (272KB bundle)
- `npm run build:bundled` - Standalone export (1.75MB bundle)

The Vite plugin automatically:
- Externalizes Phaser from your bundle
- Generates virtual modules that load from `window.__venusLibraryExports`
- Injects configuration for the Venus host to provide libraries
- Serves CDN assets from local `cdn/` folder during development

**When to use bundled mode:**
- Distributing standalone HTML5 games outside Venus
- Testing without the Venus host
- Creating web-only exports

## Project Structure

```
├── public/
│   └── assets/          # Small static assets bundled with app (icons, UI elements)
├── cdn/                 # Large static assets deployed to CDN
│   ├── assets/          # Your large images, sounds, music, etc.
│   └── README.md        # CDN usage guide
├── src/
│   ├── scenes/          # Phaser scenes with VenusAPI integration
│   ├── main.ts          # Entry point with VenusAPI initialization
│   └── style.css        # Global styles
├── node_modules/
│   └── @series-inc/venus-sdk  # VenusAPI SDK
├── game.config.json     # Generated by `venus create-game` (gitignored)
├── index.html           # HTML template
├── tsconfig.json        # TypeScript configuration
└── vite.config.ts       # Vite configuration with embedded libraries plugin
```

### Key Files

- **`game.config.json`**: Generated by `venus create-game`. Contains your unique `gameId` (UUID) used by the Venus CLI for deployments. This file is gitignored - each project generates its own.
- **`vite.config.ts`**: Uses `venusLibrariesPlugin()` which auto-detects your app name from the folder path and handles CDN asset serving in development.
- **`package.json`**: Contains the standard dev/build scripts (`dev`, `build`, `build:bundled`, `preview`).

## VenusAPI Integration

The template already initializes VenusAPI in `src/main.ts` and showcases logging, storage, and lifecycle hooks in the default scene. Treat that code as a reference and trim or expand it to match your project.

- Always await `VenusAPI.initializeAsync()` before using SDK calls.
- Scenes can implement optional lifecycle helpers (`onShow`, `onPause`, etc.) so you can react to app state changes.
- Prefer `VenusAPI.log()` and `VenusAPI.error()` when debugging so messages surface inside the Venus host.
- For a full API tour—including storage, popups, ads, CDN helpers, and haptics—refer to the Venus SDK section in the GitBook.

## Building Your Game

1. Start from the bundled HelloWorld scene, then add or replace files in `src/scenes/`.
2. Register new scenes inside `src/main.ts`.
3. Run `npm run dev` for local iteration. When you’re ready to publish, run `npm run build` followed by the appropriate `venus update-and-publish-game` command from the Venus CLI docs.
4. Use the GitBook docs whenever you need deeper SDK/CLI guidance, monetization features, or troubleshooting steps.

## Asset Strategy

- Keep must-have, lightweight assets under `public/assets`.
- Store large or frequently updated files inside `cdn/assets` and resolve them via `VenusAPI.cdn.resolveAssetUrl('<app-folder>/assets/your-file')`.
- The `venusLibrariesPlugin()` automatically serves CDN requests from the local `cdn/` directory during development and keeps the same structure for production deployments.
- Review the CDN/asset section of the GitBook for advanced workflows or environment-specific considerations.
